# การต่อสู้แบบชุด
อ่าน batch_combat.py และ early_combat.py ครั้งเดียวตอนเตรียมฉาก ใช้ run(state, duration_ms, stop_hp_ratio) ครั้งเดียวต่อคำสั่ง รายงาน summary และ reason สั้น ๆ บันทึก state ทั้งก้อนรวม queue/sequence/counter หลังแต่ละคำสั่ง ไม่ค้น source แก้โค้ด หรือรันทดสอบซ้ำระหว่างคำสั่งปกติ

รองรับเฉพาะโปรไฟล์ Novice ที่มีบัฟและ Knife กับ G_PORING ตาม early_combat.py ไม่มีสกิล อุปกรณ์อื่น หรือระบบเลเวลสูงครบถ้วน คิวรองรับหลายเหตุการณ์ แต่ไม่ได้ยืนยันสูตรต่อสู้เลเวลสูง

ก่อนใช้ ตรวจสถานะจริงตรงโปรไฟล์ รวมวันหมดบัฟและ regen/world events แล้วตั้ง valid_until เป็นเวลาของเหตุการณ์ที่ยังไม่รองรับที่ใกล้ที่สุด ห้ามเดาเวลาเพื่อข้ามเหตุการณ์ เมื่อ reason=world_event ให้จัดการเหตุการณ์นั้นก่อนต่อ ห้ามขยาย valid_until โดยไม่อัปเดตกลไก

new_state ใช้เฉพาะสร้างสถานะครั้งแรก: ใส่เวลาปัจจุบัน seed/counter HP และ next_player_start/next_mob_start จากเซฟจริง ห้ามรีเซ็ตคูลดาวน์ หากมี damage ที่รออยู่ต้องแปลงเป็น queue ให้ครบก่อนเริ่ม ห้ามเรียก new_state ซ้ำทุกคำสั่ง ใช้ state จากผลครั้งก่อน

CLI: python chat-rpg/runtime/batch_combat.py request.json
request: {"state": <สถานะจากครั้งก่อน>, "duration_ms": 5000, "stop_hp_ratio": 0.5}
ผลเป็น JSON ไม่มีการเขียนเซฟอัตโนมัติ ให้ GM บันทึกผลอย่างปลอดภัยหนึ่งครั้งต่อคำสั่ง และสำรอง GitHub เป็นช่วง ไม่จำเป็นต้อง commit ทุก hit

reason=defeat หมายถึงหยุดก่อนขั้นตอนผลแพ้/ชนะ ต้องใช้กฎ EXP ของดรอป เควสต์ และความตายแยกต่างหาก ห้ามถือว่าผลตอบแทนเสร็จแล้ว
hp_threshold เป็นจุดหยุดตัดสินใจ เวลาโลกหยุดระหว่างรอคำสั่งตามรูปแบบเกมแชท
การเรียงเหตุการณ์เวลาเดียวกันใช้ลำดับการเพิ่มคิว เป็นการปรับสำหรับแชท

ทดสอบแล้ว: คำนวณ 5000ms ครั้งเดียวให้ state เท่ากับ 700+4300ms, หยุดเมื่อตาย, ไม่แก้อินพุต, หยุดก่อน buff/world boundary, ต่อจาก HP42/45 กับศัตรู16/55 และเวลาสวนกลับที่ค้างอยู่ ตัวอย่าง 10000 encounters เฉลี่ยประมาณ0.063ms เฉพาะโปรแกรม ไม่ใช่เวลาตอบ AI หรือผลทดสอบเลเวลสูง
