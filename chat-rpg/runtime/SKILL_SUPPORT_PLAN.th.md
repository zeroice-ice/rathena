# ขอบเขตการเพิ่มสกิลในการต่อสู้แบบชุด
สถานะ: ข้อกำหนดที่ผู้เล่นร้องขอ ยังไม่ใช่ระบบสกิลที่ทำเสร็จ
batch_combat.py ปัจจุบันรองรับโจมตีปกติเท่านั้น ห้ามรายงานว่ารองรับสกิลจากการมีเอกสารนี้

เป้าหมาย: คำสั่งใช้สกิลระหว่างต่อสู้ต้องผ่านโปรแกรมเดียวกับคิวโจมตี โดยโหลดข้อมูลก่อนฉาก ไม่วิจัยหรือเขียนระบบระหว่างแต่ละ hit
ครอบคลุมสกิลโจมตีกายภาพ เวท หลายฮิต พื้นที่ ฮีล บัฟ ดีบัฟ สถานะผิดปกติ สกิลติดตัว และสกิลอัตโนมัติ แต่แต่ละสกิลต้องมี handler และหลักฐานทดสอบก่อนเปิดใช้

การตรวจ: เรียนสกิลแล้ว ระดับสกิล อาชีพ อาวุธ SP/HP วัตถุดิบ เป้าหมาย ระยะ แนวสายตา แผนที่ สถานะห้ามใช้ เวลาร่ายคงที่/แปรผัน การยกเลิกร่าย after-cast delay cooldown และการโจมตีปกติที่ค้างอยู่
การประมวลผล: เหตุการณ์เริ่มร่าย จบร่าย แต่ละ hit tick ของสกิลพื้นที่/ต่อเนื่อง และบัฟหมดอายุ อยู่บนเวลาเดียวกับศัตรู สั่งสกิลไม่ได้หยุดศัตรู
ต้นทุนต้องหักตามจังหวะที่ source กำหนดและไม่หักซ้ำเมื่อโหลดเซฟ คิวและ RNG ต้อง replay ได้
การควบคุม: สั่งต่อสู้ช่วงสั้นแล้วสั่งสกิล หรือระบุแผนล่วงหน้า เช่น ใช้ฮีลเมื่อ HP ต่ำกว่าเกณฑ์ ต้องตรวจสกิลและเงื่อนไขทั้งหมดก่อนเริ่มชุด ห้ามแทรกคำสั่งย้อนหลัง
ผลแพ้/ชนะ EXP ของดรอป quest และ regen ต้องมี handlers ก่อนอ้างว่าจบฉากครบถ้วน

แหล่งตรวจ: db/re/skill_db.yml, skill_tree.yml, src/map/skill.cpp, src/map/skills/, battle.cpp, status.cpp และ conf/battle/
ตัวอย่างตรวจแล้ว: NV_FIRSTAID Id142 MaxLevel1 TargetSelf SP3; SM_BASH Id5 TypeWeapon TargetAttack SP8 ที่ระดับ1..5 และ SP15 ที่ระดับ6 เป็นต้น ข้อมูลเหล่านี้ไม่เพียงพอสำหรับสูตรผลลัพธ์ ต้องอ่าน implementation เพิ่ม

ลำดับส่งมอบ: สกิลที่ตัวละครเรียนจริงก่อน จากนั้นเตรียมสกิลอาชีพถัดไปก่อนเปลี่ยนอาชีพ รักษาทะเบียน supported/unsupported รายสกิล ห้ามอนุมานว่ารองรับทุกสกิลจากโครงสร้างคิว
การทดสอบ: ศัตรูโจมตีระหว่างร่าย SPไม่พอ ยกเลิกร่าย cooldown บัฟหมดอายุ เป้าหมายตายก่อนสกิลออก หลายฮิต save/load ระหว่างร่าย และผลชุดยาวเท่ากับแบ่งชุดสั้น รวมถึงทดสอบความเร็วแยกจากเวลาตอบ AI
